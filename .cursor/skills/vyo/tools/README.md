# vyo poster tools

`vyo` reads a repo, writes a scaffold spec for a poster, sketches the agent's figure as text, and renders the filled spec to HTML, PNG and PDF. The contract between the pieces is [CONTRACTS.md](CONTRACTS.md). The package README for users is [../README.md](../README.md).

## Commands

Run them from the target repo as `npx vyo …` once `@litterthanlit/vyo` is a dev dependency, or as `npx -y @litterthanlit/vyo …` without installing it. Paths are relative to the working directory.

| Command | What it does |
|---|---|
| `vyo init [--cursor] [--claude] [--codex] [--dir <repo-dir>]` | Copies `SKILL.md` and its three docs into `.cursor/skills/vyo/` and/or `.claude/skills/vyo/` of the repo (default `.`; the editor folders it has, or both if it has neither). `--codex` adds one marked block to `AGENTS.md` that points at the skill. A rerun overwrites the same files and replaces the block. Prints each path it wrote |
| `vyo scan <repo-dir> --out <dir>/<repo>-facts.json` | Reads the repo and writes `facts.json`. Never writes inside the repo except to `--out`. Tests, hidden folders, and `dist`, `build`, `out`, `vendor`, `public`, `static` and `assets` at a repo or package root are left out, and `scan` prints how many files and lines. When all the code is in a hidden folder such as `.cursor/`, `scan` and `show` name it; run `scan` on that folder |
| `vyo show <facts.json>` | Prints a plain summary of the facts |
| `vyo parts <facts.json> [--field wave\|terrain\|river\|shape\|radial\|sphere\|scatter\|shatter\|glyph\|bleed\|slabs\|spiral\|contour] [--split <part id>]...` | Prints the parts a field draws, with that field's part defaults: id, share of lines, lines, files and scanned name, with `! looks like a vendor or code name` after each unplain name and `! same name as <id>` after each name another part shares. When one part holds over 75% of the lines, or there are under 4 parts, a last `!` line names it with its share and what `--split <its id>` gives (the parts and the largest share), or says it has no folders to split. `--split` (shape only) previews a region's `split` |
| `vyo shapes [--log <file>]` | Lists every field with its one-line description and how recently compose used it (`last used N ago` or `never`), from `./vyo/recent-shapes.json` unless `--log` names another |
| `vyo presets [<id>]` | Lists the presets with id, `fits`, and a summary of regions and texts. With an id, prints that preset's figure as JSON |
| `vyo compose <facts.json> [--frame loose\|swiss\|signal] [--field wave\|terrain\|river\|shape\|radial\|sphere\|scatter\|shatter\|glyph\|bleed\|slabs\|spiral\|contour] [--style rings\|relief\|symbols] [--split <part id>]... [--seed <n>] [--accent <part id>] [--from <preset>] [--repo <dir>] [--theme light\|dark] [--out <spec.json>] [--shapes-log <file>] [--force]` | Writes a scaffold spec. Without `--from`, the figure is a field, in the loose frame unless `--frame swiss` or `signal`; loose and signal print the corners the field leaves. With no `--field`, it picks a generated field other than wave and shape and records it, and offers `--field shape`; `--style` alone means `--field shape`; without it the style is `relief`. `--field shape` (loose or signal) writes a placeholder `shape` that render rejects, a label, headline, legend and paragraph with no coordinates (the engine places them), the region's `split` and `style` (`relief` unless given), a legend placeholder in that style's words (`… at most 2 sentences and 180 characters, like "Every layer is a part of <product>, as big as its code. The orange layer is <the accent's plain name>."`; rings say ring and area, symbols a band of marks), and prints the shape format in a few lines. Refuses to overwrite an existing spec unless `--force` is given |
| `vyo sketch <spec.json> [--facts <facts.json>]` | Prints the sheet as ASCII, with coverage, each fill region's width spread and mean width, and the floor; a loose or signal spec also gets the field's four empty corners. A figure with a field reads the facts. A shape field adds its strata (a relief: the light as `·:-=+*#` and its predicted thumbnail) or its rings, its share of the sheet and its `shape-*` findings, each as `✗ <id>:` or `! <id>:` at the level render gives it, and writes `<repo>-sketch.png` beside the spec (a relief's is the shaded thumbnail it predicts). Then every check that needs no browser: the spec's errors as `✗ spec:` lines and every spec-stage check (legend, fits, part names, facts) as `✗` or `!` lines. Needs no browser |
| `vyo render <spec.json> [--out <dir>] [--facts <facts.json>] [--no-png] [--no-pdf] [--gif] [--paper fit\|a4\|letter]` | Validates the spec, writes HTML, a 2× PNG and a PDF, then runs every check. `--gif` also writes a 560px GIF and an 840px MP4; the spec must have `motion` |
| `vyo check <spec.json> [--facts <facts.json>]` | Runs the same validation and checks in a temporary directory. Writes nothing to `--out` |

Exit codes: 0 when everything passes (warnings go to stderr as `! ` lines), 1 on any rule error (`✗ ` lines on stderr), 2 on a usage error.

`compose` fills `product`, `facts`, `theme` and `frame`. In the loose frame (the default for a field), compose lays the field out, finds its empty corners, and places `label`, `headline`, `legend`, a `paragraph` and a `list` of the parts into them by the rule in [Frames](#frames); it writes no notes, prints the corners and one line per text role, and warns when there is no `--repo`, since the record line needs the commit. The rest of this paragraph is the swiss frame. Without `--from`, the figure is one field region. `--field` names it. With no `--field` (and no `--style`, which means a shape), compose picks a registered field other than wave and shape, which waits for the agent to draw it, (one not in `recent-shapes.json` beside the spec, chosen by the facts hash so two repos start on different shapes, or the least recently used if all of them are), prints `picked <field> (avoided recent: …)`, and appends that field to the log (8 entries, newest last; `--shapes-log` overrides the path; `--from` does not record). It writes a non-zero `seed` unless `--seed` is passed (`--seed 0` is the identity), and for a glyph a `letter` from the repo name. `accent` is set from `--accent`, a placeholder goes in `names` for every part, a placeholder `sentence` for a wave, and a masthead, headline and aside placed where that field leaves room. The spec has no `hot`. A scan with no code has no parts, so `compose` refuses a field there with `✗ no parts to draw; the scan found no code` and points at `--from`. With `--from <preset>`, the figure is a fill preset's, with its geometry kept and its words replaced by placeholders; `--from` refuses a field preset and names the `--field` to use instead, and refuses `--field` or `--accent` beside it. `--accent` must name a part. Render rejects every placeholder. `compose` prints `floor: <y>` for the spec's notes count, assuming a one-line not-built list, then the `masthead`, `headline` and `aside` lines: line heights and characters per line. A field scaffold adds a line pointing at `vyo parts` and a `field:` line; a preset scaffold adds the `rows` line. Each extra not-built line raises the floor by 16px.

`compose --repo <dir>` reads the latest commit's short hash and commit date with git, so reruns give the same footer or record line. Without `--repo` the spec has no commit and `date` is today.

`sketch`, `render` and `check` read the facts from `--facts`, or by default from `<repo>-facts.json` beside the spec, where `<repo>` is the spec's `product.repo`. Output goes to `--out`, by default the spec's directory: `<repo>-poster.html`, `<repo>-poster.png` and `<repo>-poster.pdf`. The HTML embeds its fonts, so it opens anywhere.

## Setup

To work on the tools, run these from the package root, the skill directory.

```bash
npm install
npx playwright install chromium   # or set VYO_CHROMIUM=/path/to/chromium
```

The fonts, Commit Mono and Newsreader, are bundled in `fonts/` at the package root under the SIL Open Font License (`fonts/LICENSE.md`). The masthead uses Inter Display if it is installed, then Inter, then Helvetica or Arial. The tools never download Helvetica.

## The spec

The spec, `<repo>-poster.json`, is the only file the agent edits. `compose` fills `version`, `facts`, `product` and `theme`. The agent writes `figure`, `headline`, `hot` (optional when the figure has a field), `notes` and `notBuilt`, may set `accent` and `audience`, and replaces `product.name` with the customer-facing name. The full type and validation rules are in [CONTRACTS.md §3](CONTRACTS.md#3-the-spec). Every preset as a full spec, and three invented figures, are in [examples.md](../examples.md).

A spec has a `frame`, `loose` (the default), `swiss` or `signal`; see [Frames](#frames). A figure has 1 to 6 regions and 1 to 14 texts, and a `fits` sentence (at most 160 characters, printed by `presets`, never drawn): on the field region when the figure has a field, else on the figure.

- A **field region** draws the repo itself: its rows come from the parts of `facts.json` at render time, and the agent picks only the field, the accent part and plain names. At most one per figure. See [Fields](#fields).
- A **fill region** is an outline that the tool fills with rows of the region's `words`, 2 to 14 of them, each at most 24 characters.
- A **dots region** spells 2 to 4 words of at most 5 letters each in squares, at `x`, `y` with a `cell` size in px.
- A **text** in the swiss frame is a `masthead` (exactly one, the product name), a `headline` (at most one, the spec's headline), a `display` (a bold sans line, at most 40 characters, size 32 to 64, default 56), an `aside` (size 10 to 14) or a `label` (size 10 to 32, default 12, and 26 when `hot`), placed at `x`, `y` with a wrap width `w`. `align` is `left`, `right` or `center`.

- A **text** in the loose frame is a `label`, `headline`, `paragraph`, `legend`, `list` or `rule`; see [Frames](#frames).
- A **text** in the signal frame is those, plus `meta`, `display` and `mark`.
- A **routes region** is 1 to 6 open SVG hairlines (`paths: [{ d, tone }]`) and optional nodes `{ path, t, tone }` that travel them when `motion.kind` is `nodes`.

Region and text ids are lowercase and unique. `note`, `counts`, `notBuilt`, `provenance`, `credit` and `record` are render's block names, so a region or text cannot take them.

## Frames

`frame: "swiss"` is the v4 poster, unchanged: masthead, serif headline, hairline, counts, note columns, not-built list, provenance and credit. It takes fill, dots and field figures, and requires `notes` and `notBuilt`.

`frame: "signal"` is the high-contrast poster: charcoal or cream paper, one signal colour, a grotesque headline, archival `meta`, optional highlighter `mark`s. It needs a field or a fill. Type may sit on the field. Same record line as loose. Extra roles, from `ROLES.signal`: `meta` (0 or 1, 11px mono caps, at most 80 characters), `display` (0 to 2, 96px grotesque, at most 8 characters), `mark` (0 to 3, a block of the signal colour, no text, needs `h`).

`frame: "loose"` (the default) is the i-loose frame. It needs a field region, has no masthead, hairline, counts, notes or footer, and lets the field bleed off every edge it reaches: its floor is the sheet's bottom edge. No text may sit on the field. Its text roles, from `ROLES.loose` in `lib/frame.mjs`:

| Role | Count | Size | What it prints |
|---|---|---|---|
| `label` | exactly 1 | 13px mono caps (11 to 16) | the product name |
| `headline` | exactly 1 | 42px Newsreader (32 to 60; a relief stacks it as large as fits), the only large type | `spec.headline` |
| `paragraph` | 0 to 2 | 15px Newsreader (13 to 17) | `text`, at most 220 characters and 2 sentences |
| `legend` | exactly 1 | 15px Newsreader (13 to 17) | `text`, at most 180 characters and 2 sentences, saying what the picture encodes |
| `list` | 0 or 1 | 13px mono (11 to 14), one per line | `parts: true` for the field's parts' plain names, or `items` (1 to 16, at most 24 characters each) |
| `rule` | 0 or 1 | 13px mono (11 to 14) | `text`, one character repeated across `w` |

**Legend.** It names the accent part's plain name and the field's measure: a word starting with "code" or "lines" for a wave or terrain, plus "files" or "wide" for a terrain, "merge", "join" or "flow" for a river, and for a shape "code" or "lines" plus "type", "size", "big", "bigger" or "larger". Otherwise `✗ legend: must say what the picture encodes; name the accent part ("<name>") and the measure (<words>)`.

**Fits.** A field region's `fits` (required, at most 160 characters, never drawn) says why this field matches the product's story, with a word that starts with one of the field's keywords: wave "travel", "flow", "hand", "move"; terrain "big", "weight", "matters", "most"; river "merge", "join", "many", "one"; shape "object", "thing", "picture", "shape", "looks". The agent quotes it in the chat reply.

**Record.** Render writes `<name> at <commit>, <date>. Drawn by Vyo.` in 10px mono with the accent full stop, along the bottom edge, or rotated up the left edge when the field covers the bottom. `record: "bottom"` or `"left"` chooses. It needs `product.commit`; `compose --repo` fills it.

**Corners.** `corners()` in `lib/geometry.mjs` returns the largest empty rectangle the field leaves at each sheet corner (on a 20px grid, at least 220px wide when possible, height counted up to 400px, overlaps on an edge split). Compose places the headline in the largest corner, the label in the smallest, the list in the tallest and the legend in the one nearest the accent part, with a paragraph where room is left, 40px from the sheet's edges and 16px from the field. `sketch` prints `corners: top-left at <x>,<y> is <w> by <h>; top-right at …; bottom-left at …; bottom-right at …`. The full rules are in [CONTRACTS.md §3b](CONTRACTS.md#3b-frames-legend-fits-record-and-corners).

## Fields

A field region is `{ kind: "field", id, field, fits, accent?, names?, sentence?, every?, seed?, letter?, symbols?, shape?, style?, echo?, bevel?, strata?, split?, minShare?, maxParts? }`. `seed` 0 is the identity pose. Thirteen fields ship, one entry each in the registry `FIELDS` in `lib/fields/index.mjs`:

| `field` | What it draws | Takes |
|---|---|---|
| `wave` | One row of a part's name per share of lines, at least one row per part, in tree order, bent into one band that enters at the top behind the masthead, swings right, back left and leaves through the floor. 6.9px letters on 7.9px rows, about 110 above the floor; the band runs on behind the text blocks, which carry a 6px paper outline. On light the accent part is `ink`, parts near the top of the tree violet (`wave`) and deeper ones a lighter violet (`wave-soft`); on dark the accent is `hot`, the others `mid` and `soft` | `sentence` (at most 40 characters, set in every `every`th row, default 5), `seed` |
| `terrain` | One peak per part, height by lines and width by files, left to right in tree order, 6.9px letters on 7.6px rows. Each row reads the name of the part whose slope it crosses, whole words only at a border, letters spread on steep slopes and tight on flats; the rim is `ink`, the rest `mid`, brighter on slopes that face left. A part narrower than 40px gets 40px, and shows as a pointed foothill under a bigger neighbour | `seed` |
| `river` | One stream of `0`s and `1`s per part entering the left edge, as thick as its share of lines, merging pair by pair by how many imports tie them into one channel that leaves the right edge, after g-flow. 5px digits in 3.1px cells on 5px rows; no part name is printed. The accent part's stream and a short run at the last merge are `hot`; other streams alternate `ink` and `mid`. Parts default to `minShare` 0.002 and `maxParts` 24 | `seed` |
| `shape` | A silhouette the agent draws for the product (`shape`), filled by its `style` over the same mask: `relief` (the default), `rings` or `symbols`, each below. Loose or signal frame. Parts default to `maxParts` 12 (14 in relief) | `shape` (required), `style` (`relief`, the default, `rings` or `symbols`, below), `echo` (rings only), `bevel` and `strata` (relief only), `split` (1 to 4 part ids: each leaf part's files start in their own folders, so a part that is most of the code becomes several) |
| `radial` | A triangle of type from an apex near the top, chords widening down the page, one row per share of lines. Accent rings take the signal colour on charcoal | `seed` |
| `sphere` | A 3×5 grid of type-built ellipses that flatten down the page, one cell per share of lines | `seed` |
| `scatter` | Separate clouds of part names, with gaps between the ellipses | `seed`, `symbols` |
| `shatter` | A grid of cells broken along a fault, some cells dropped | `seed`, `symbols` |
| `glyph` | One giant letter filled with part names | `letter` (A–Z or 0–9), `seed`, `symbols` |
| `bleed` | One large form whose centre is off the sheet, so the type runs off an edge | `seed`, `symbols` |
| `slabs` | Stacked slabs of type with gaps between them and staggered ends | `seed`, `symbols` |
| `spiral` | A thick Archimedean coil, not a sine | `seed`, `symbols` |
| `contour` | Nested rings around a few Gaussian hills | `seed`, `symbols` |

`symbols: true` on a mask field (every field from `scatter` to `contour`) draws the shape in `-`, `:`, `=`, `+` and `#` instead of the parts' names: the deeper inside the form a cell sits, the denser its symbol, and smooth noise leaves gaps so the form breaks into clusters. Parts still share the rows by lines, and the accent part's rows take the accent colour. The `wings` preset is the worked example.


**A traced shape.** `shape: { mask, fit? }` instead of `ops`: `mask` is a bundled name (`wings`, `trace` in `tools/presets/masks/`) or a path to a PNG, absolute or relative to the working directory. Any non-interlaced PNG up to 4096px a side reads, palette and alpha included (alpha composites on white). Its pixels darker than mid grey, trimmed to their box and sampled down to 1200px on the long side, are the silhouette: the mask is fitted like a drawn one, and every style, check and the placement read it the same way. A traced shape takes no `ops` and no `rotate`. A missing or unreadable mask fails sketch and render with `✗ spec: figure.regions[0].shape.mask: shape mask …`.

**The symbols style.** `style: "symbols"` draws the shape in `-`, `:`, `=`, `+` and `#`, 7px type on 8.4px rows, by the symbol rule of the generated fields: smooth noise leaves gaps, more of them near the edges, and depth picks the symbol. Depth is a dome from the outline in, reaching 1 at 0.22 of the deepest point, times light from the top left (0.4 of it), so the form shades as a volume. The parts share the rows top to bottom by lines, at least one row each, and the accent's rows take the accent colour (on paper in the signal frame, ink on a highlighter block). No name prints, so `shape-name` does not apply; the style's own `shape-accent` asks for 40px of accent rows. The sketch PNG shades each symbol by how much ink it lays.

**The rings style.** `style: "rings"` sets the parts' names along inward offsets of the outline instead: the mask's signed distance field (an exact Euclidean distance transform of its pixels) gives one iso-line every 7px from 3.5px inside the outline, rounded over up to 14px. Ring order encodes nothing; area does. The outermost ring is a rim, held by the part whose share is nearest that ring's area; the accent comes next as a band of whole rings, so it traces the outline one ring in as one closed band, as many rings as come nearest its share and at least two (one ring, 7px, does not show at thumbnail size; the sketch says when the floor holds). The other parts follow in tree order, the rim's part first with what its ring left of its share, and split what lies inside in proportion to their lines, so the rim's and the accent's rounding spreads thin. Among them a ring's area is spread evenly round it, so a part may end part way round a ring and the next part takes the rest; the boundary steps in by one ring there, at the bottom of the loop (the seam). Each of them spans room for two copies of its name. A loop that runs more than 30% of its length within 4px of the shape's skeleton, and the innermost 10% of the shape's area, become a core: a fill of its own (`cold` on dark, `cool` on light) set in level lines 7px apart, run top to bottom by the parts that are left. Names are set glyph by glyph in 6.6px Commit Mono, whole names only, with a middle dot between two names; a name that would bend more than 24 degrees between two letters, touch the skeleton or land within 4.75px of a name already set is left out, outer rings first, so no two glyphs overlap. A name runs left to right whichever way its ring turns, so the bottom of a ring reads upright too. The accent part's rings and core lines are filled with `hot` and set in bold `on-hot`. A hairline marks each boundary between parts and the core's edge. On dark the rings are `ink` on paper; on light the whole shape is `ink` with the type and hairlines in `paper`, because ink type on paper read as a grey outline at thumbnail size. `echo` (0 to 12) draws that many hairline copies of the outline outside it, 9.8px apart, in `soft`, fading outward, broken 16px clear of every text block. A rings shape suits a fat, round object, with a cut in it for the legend if wanted; a thin one starves the rings, and `shape-rings` says so.

On paper the terrain's letters take 0.14 more alpha and its accent 0.5 more (0.3 on dark), as in i-loose.

- `accent` is a part id, an area id or a glob over part ids (`area:lib/*`). An area that merged into a bigger part names that part; an area that holds parts names all of them. The accent parts are drawn in `hot` and carry `data-hot`. Without it, `check` warns `accent-part`.
- `names` maps part ids to plain names of at most 24 characters, checked for jargon like any copy. A part's row text is its name in lower case.
- Rows skip the text blocks with 12px to spare, so moving a text block makes room; a part whose every row is covered fails `field-parts`.

**The shape format.** `shape` is `{ ops, rotate?, fit? }`. `ops` (1 to 24) are painted in order into one mask: each has exactly one verb key, `add`, `cut` or `crease`, whose value is the kind, and the first must be an `add`. A `crease` never paints: only the relief style reads it. Coordinates are free units with y down; the engine measures what was painted, cuts and rotations counted, and fits it.

| Kind | Keys |
|---|---|
| `circle` | `at: [x, y]`, `r` |
| `ellipse` | `at`, `r: [rx, ry]` |
| `rect` | `at` (top-left), `size: [w, h]`, `round?` (corner radius) |
| `capsule` | `from`, `to`, `r` (a thick line with round ends) |
| `arc` | `at`, `r`, `from`, `to` (degrees clockwise from twelve o'clock), `width` |
| `polygon` | `points` (3 to 40), `round?` |
| `path` | `d`, an SVG path filled nonzero |

Any op takes `rotate`, degrees clockwise about its own centre; the shape's `rotate` turns the whole. Without `fit.w` or `fit.h` the shape is as large as fits inside 40px side margins, 250px of room for the words at the top and 56px for the record line at the bottom, standing on that bottom margin, whatever its aspect, and never bleeds (`SHAPE_ROOM` in `lib/mask.mjs`); text placement then moves it into the room its words leave (see Text placement). `fit.w` and `fit.h` set its width and height as shares of the sheet's instead (over 1 bleeds off; with both, the smaller scale wins), and `fit.cx`, `fit.cy` place its centre (default 0.5, 0.61 when a size is given). `lib/mask.mjs` paints the ops into rows of spans at sheet resolution, and the rows, the corners, the record line, the sketch and the `shape-*` checks all read that mask.

**Text placement.** On a shape poster a text block may leave out `x` and `y` (and `w`, then its role's widest). `lib/place.mjs` places such blocks before render and sketch read the spec, so both put them in the same spot: label, headline, legend, paragraphs and list stacked in that order in one column (label 10px above the headline, the others 22px apart), or the label and headline apart from the rest, or each alone, in the first room from the top that keeps 40px off the sheet's edges, 20px off the shape and 10px off the record line, flush to the nearer sheet edge and aligned away from the shape. When the shape has no `fit.w`, `fit.h` or `fit.cy` and no block is pinned, the shape moves for the words: if they do not fit in one column above it, it moves down (shrinking to no less than 85% of its size) until the label, headline and legend do, and the rest go where there is room; and when every block sits above it, it grows into the room they leave and centres in it, 32px below the words at least. Sketch and render read the same moved shape. Column widths run from each role's widest (headline 520, legend and paragraph 300, list 240, label 300) down to its narrowest in 20px steps; the headline tries 42, 38, 35 and 32px, wrapped by Newsreader's own advances. A relief stacks its headline: as large as fits, from 60px down, in the narrowest column that holds it in four lines, with the legend under it. Only when the shape cannot make that room are the label and headline split from the legend, or every block placed alone. Every grouping is first tried with the headline at least 400px wide, so a headline is split from the legend before it is squeezed into a gap in the shape. The room is reserved for 1.12 times the role's average advance. Blocks with `x` and `y` keep them and the others keep clear of them. When nothing fits, the blocks go top left and `shape-room` says how much to shrink the shape.

**The relief style.** `"style": "relief"`, the default (`lib/fields/shape-relief.mjs`, one entry in `SHAPE_STYLES`), draws the mask as a lit volume in 6px Commit Mono. On a 2px grid it takes the distance to the outline, rounds it into a dome (`bevel`, 0 to 1, default 0.7, is the share of the deepest point that is rounded), softens it, adds a pillow off each seam between strata and a 14px valley along each crease, and lights it from the top left. Strata cut the area among the parts in tree order, each its share of the lines: `{ by: "angle", angle }` stacks them along a direction (90, the default, top to bottom; 135 from top right to bottom left), `{ by: "depth" }` makes shells from the outline in. Only the type draws the form. Each glyph line is set word by word: a word runs to its end across any seam and stops only at the outline, and takes whichever part under its next 14 cells is owed the most cells, so glyph shares follow the lines while the strata stagger where names begin and end. A line enters the shape partway through a name. A part still without a whole name writes it once over the stretch of a line that holds most of its cells. Hints the other styles ignore: `face: "lit"` or `"dim"` on an add makes it a flat facet toward or away from the light; `{ crease: kind, ... }` folds the surface along the kind's outline, or along a `capsule`'s or `arc`'s centre line (its `r` or `width` may be left out). The letters are `ink` on either sheet, stronger and bolder where lit on the dark sheet and where shaded on paper; gaps between names take `·` or `:`, or stay empty where the ink is faint. There is no outline, body or haze. The accent part is bold `hot` over a glow that hugs its letters (7px blur on the dark sheet, 5px on paper). Outside the shape a faint dot grid covers the sheet, and the form's shadow, cast down and right, takes dots away on the dark sheet and darkens them on paper.

**Parts.** `vyo parts <facts.json>` prints them. Every non-generated file starts in its nearest leaf area, or in its own area when no leaf holds it. A part under `minShare` of the lines (default 0.02) merges into its parent area, deepest first, until it is big enough or sits at the top level. Then the smallest parts merge up until there are at most `maxParts` (default 14). The parts hold every line exactly once. A name is flagged as unplain when it is all caps, holds a company name the scan knows, or is one word ending in a digit.

## Geometry

A fill region has exactly one of these four, listed in the order to prefer them. All numbers are sheet px on the 840×1190 sheet.

| Field | Shape | Limits |
|---|---|---|
| `profile` | `[[y, cx, halfWidth], ...]`. A smooth outline through the stops, from the first y to the last | 3 to 24 stops, y strictly increasing |
| `ellipse` | `{ cx, cy, rx, ry }` | |
| `polygon` | `[[x, y], ...]`, closed | 3 to 40 points |
| `path` | An SVG path string with M, L, C, Q, A, H, V and Z, absolute or relative | Must parse |

`holes` is an optional list of the same four shapes, cut out of the region with the even-odd rule. Region options: `band` (1 to 4 rows per word, default 1), `size` (7 to 12, default 12), `caps` (default true) and `hot` (every row in the accent).

Rows sit on a sheet-wide grid of 16px, or 14px at size 11. The tool skips any part of a row within 12px of a text block and drops runs narrower than 24px. [CONTRACTS.md §4](CONTRACTS.md#4-geometry) has the sampler rules.

## Tones

A fill region's `tone` is one token, or a list of 2 or 3 tokens that step down the region. Each row takes the nearest stop, so a pair gives the top half the first token and the bottom half the second. Three tokens give the eye's lids their soft, mid, soft bands. A dots region's `tones` has one entry per line, and a line may be `hot`.

| Token | Use |
|---|---|
| `soft` | Far, past, background |
| `mid` | Between |
| `ink` | Near, now, the plain foreground |
| `cold` | A blue-grey for a state that has not started |
| `cool` | A darker blue-grey, one step warmer |

Both themes define all five, plus `paper` and `hot`. `accent` in the spec replaces the theme's `hot`. Anything in the hot colour is the hot word: rows whose word matches `hot`, rows of a region with `hot: true`, a dots line with tone `hot` or a word matching `hot`, and a label with `hot: true`.

## Sketch output

`vyo sketch` draws the sheet at 20px per character, 42 columns by about 60 lines, without a browser. It runs the same row sampler as the page on a polygon version of each outline. Profiles and ellipses become exact polygons, and paths are flattened. Text widths are a Node estimate from per-character advances, not the browser's measurements, so a text box or a word near a run's edge can land a few pixels off.

| Mark | Meaning |
|---|---|
| `A` to `F` | Rows of the first to the sixth fill or field region, in spec order |
| `#` | Squares of a dots region |
| A box | A text block labelled with its id, with its height estimated: 88px for a masthead line at size 84, 28px per headline line in a 224px column, 7.2px per character of mono text, one line of the size's height for a display |
| `=` | The footer's top line (swiss only) |
| `·` | A hot row |

A field's rows come from the same layout module the page runs, given the estimated text blocks and Commit Mono's 0.6em advance; with the page's own text blocks the two place every row within 2px. Its legend entry reads `A wave (wave, 13 parts, 85 rows)`.

A shape field draws its mask instead of rows: its letter where the shape is, `@` in the accent (in rings, where the accent's fill is). Under `regions:` it prints a `shape:` line (the share of the sheet covered, the fitted size, `fit.w` and `fit.h`, and which edges it bleeds off) and the style's own lines: a relief prints its bevel and strata and the light it predicts, then one line per stratum. In rings it prints instead how many rings fit, how thick the shape is and how many rings the parts want, the core's level lines, and one line per part from the outline in: its rings, its core lines, and its share of the area beside its share of the lines; the PNG shows the fills with each glyph as a mark in its tone. It writes `<repo>-sketch.png` beside the spec, the silhouette at a third of its size as the style shades it, the accent in the accent, every crease as a line in paper, and the text blocks outlined, encoded with Node's zlib, no browser. Its `! ` lines are the `shape-*` messages, measured on Node's own layout and the placed text blocks, followed by every spec-stage check (see the `vyo sketch` row above).

Under the sheet it prints `regions:`, `texts:` and `floor:` lines (in the loose frame `texts:` includes `record`, `floor:` reads `the sheet's bottom edge (loose frame)` and a `corners:` line follows), then the coverage, height and width, each marked ok or too low, and one line per fill region with its spread of line widths (standard deviation over mean) and mean width, so the agent sees `silhouette`, `row-variety` and `thin-region` before it renders. Lines that start with `! ` flag a field part that is never drawn (`region <id>: part "<name>" (<id>) is never drawn`) or an accent that names no part, a region under 4 rows, a word that may never be drawn, anything below the floor, and the `row-variety` and `thin-region` messages.

## How it works

`scan` turns the repo into `facts.json` with no network and no model, so two scans of the same tree are byte-identical. `compose` turns the facts into a field poster, or a preset into a spec whose figure the agent writes in plain words and sheet coordinates. `render` computes each field's parts from the facts, then builds one HTML page in which `lib/fill.js` lays out each field with its module from `lib/fields/`, samples each outline into rows, fills them with the region's words, and places the texts, then Playwright waits for `window.drawn`, takes a 2× screenshot and prints a PDF. The checks run in the same page and measure what was drawn, so a rule break shows up as a `✗` line instead of a bad poster.
