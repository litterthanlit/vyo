How it works

Scan, compose, sketch, render. Then the checks decide.

The skill tells your coding agent how to read the repo, choose the picture and write the words. The vyo command does the drawing and checks the result. Run it from the repo you want to explain.

  1. 1

    Scan

    Reads the code as text into facts.json: files, lines and imports. No network, no model, and your code is never run. Two scans of the same tree give the same file.

    npx vyo scan . --out vyo/app-facts.json
  2. 2

    Compose

    Writes a scaffold spec for the look you choose. Your agent names each part in plain words, writes a one-line headline, and picks the accent: the part the product is about.

    npx vyo compose vyo/app-facts.json \
  --frame plate --plate blueprint --layout blueprint \
  --ground abyss --repo . --out vyo/app-poster.json
  3. 3

    Sketch

    A quick picture of the layout before the full render, plus every check that needs no browser, so the agent fixes the shape and the words first.

    npx vyo sketch vyo/app-poster.json
  4. 4

    Render and check

    Draws the poster in headless Chromium to HTML, a 2× PNG, a thumbnail and a PDF, and with --gif a looping GIF and MP4. Then it measures what was drawn. Any ✗ finding exits 1 and names the one change to make.

    npx vyo render vyo/app-poster.json --gif

Honest encoding

Nothing on the sheet is decoration. Each mark is a number from the scan, and the legend says which.

Size
Lines of code. A part with a tenth of the lines gets a tenth of the chamber, glyphs or strata.
Links
Real imports between areas of the code, read by the scan, never drawn by hand.
Accent
The one part you choose: the code that does the product's main job.

Checks that fail, not warn

  • plate-parts every line of the scan is conserved across the plate, and every part is drawn.
  • cover-share each part's share of the printed glyphs is within 1 point of its share of the lines, and with --gif in every frame.
  • blocks-inside text-clear labels-whole no text off the sheet, painted over, or cut short.
  • copy no jargon, file paths or placeholder text left in the words.

Install

Three commands in the project you want to explain.

  1. $ npm install --save-dev @litterthanlit/vyo
  2. $ npx vyo init
  3. $ npx playwright install chromium
  • init

    Copies the skill into .cursor/skills/vyo/ and .claude/skills/vyo/. Pass --cursor or --claude to choose one, or --codex to also point AGENTS.md at the skill.

  • Chromium

    Already have Chromium or Chrome? Set VYO_CHROMIUM to its path and skip the last command. A GIF also needs ffmpeg on the path.

  • Node

    Node.js 20 or later.

  • Try it

    Without installing: run npx -y @litterthanlit/vyo init, and have the agent run npx -y @litterthanlit/vyo wherever the skill says npx vyo.

Then say this to your agent

“Explain this app as a poster. Draw it as a shape.”

or, for a cover with its loop: “Make a cover for this app.”

The agent follows the skill and replies with the paths of a PNG and a PDF, and for a cover a GIF, in vyo/ at the project root.

What it reads

Nothing leaves your machine. The scan reads source files as text and runs only git, to read the latest commit, with hooks off. Dotfiles such as .env, hidden folders, tests, node_modules and build output are skipped.

Languages

JavaScript, TypeScript and Python get full detection: screens, requests and saved records. Go, Ruby, Rust, PHP, Java, Kotlin, Swift, C#, C and C++, Dart, Scala, Elixir, Lua and Zig are drawn by size.

Styles

When no single object fits, a field draws the parts of the code as type across the whole sheet. Shapes trace a silhouette in one of three styles.
